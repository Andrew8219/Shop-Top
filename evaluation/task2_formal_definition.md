# Формальное описание итогового набора характеристик для фильтров (Задача 2)

## 1. Объект

Для каждой категории каталога `c` формируется итоговый набор фильтров:

`F(c) = {f_1, f_2, ..., f_n}`

где каждый фильтр `f_i` соответствует нормализованному имени свойства из `property_names`, а домен значений формируется по `product_properties` после нормализации.

## 2. Правила включения свойства в фильтр

Свойство `p` включается в `F(c)`, если выполняются условия:

1. **Покрытие по категории**: доля офферов категории `c`, у которых есть `p`, не ниже порога `tau_cov`.
2. **Согласованность значений**: нормализованные значения `p` имеют достаточную консистентность.
3. **Отсутствие дублей**: имя свойства уникализировано (merge дублей).

## 3. Критерии качества набора фильтров

Используются три базовые метрики:

1. `coverage`  
   `coverage = offers_with_properties / total_offers`  
   Интерпретация: выше -> лучше.

2. `duplicates_ratio`  
   `duplicates_ratio = 1 - unique_property_names / total_property_names`  
   Интерпретация: ниже -> лучше.

3. `consistency`  
   Взвешенная доля модального значения по свойствам:
   `consistency = sum(mode_count_p) / sum(total_count_p)`  
   Интерпретация: выше -> лучше.

## 4. Практический результат в проекте

Метрики вычисляются функцией `evaluate_filter_quality()` в модуле `normalization.py` и попадают в итоговый отчет `evaluation/reports/vkr_metrics.md`.
