# Задача 7. Методология оценки эффективности

Документ для пояснительной записки: постановка эксперимента, метрики, базовые подходы.

## 1. Цель эксперимента

Сравнить качество ранжирования карточек товаров по поисковому запросу для нескольких **базовых линий** (baseline) и гибридного решения на фиксированном наборе запросов с заранее заданной релевантностью.

## 2. Тестовые данные

- Файл: `evaluation/task5_queries.json`.
- Формат записи: `id`, `query` (текст запроса), `relevant_offer_ids` (список идентификаторов релевантных офферов; допускается несколько релевантных документов на запрос).
- Разметка задаётся вручную под текущий каталог (демонстрационные данные).

## 3. Сравниваемые подходы (базовые линии)

| Обозначение | Описание |
|-------------|----------|
| **semantic_only** | Топ результатов по косинусной близости (внутреннее произведение нормированных векторов) запроса и пассажей в индексе **FAISS** (или **pgvector**, если FAISS недоступен). Модель эмбеддингов: **multilingual-e5-small** (sentence-transformers), префиксы `query:` / `passage:`. |
| **text_only** | Полнотекстовый поиск **PostgreSQL**: `tsvector` + `websearch_to_tsquery('russian', q)`, ранжирование `ts_rank_cd`. |
| **hybrid_rrf** | Объединение списков **semantic** и **text** методом **RRF** (Reciprocal Rank Fusion), параметр `k=60`, до 100 кандидатов; затем **постфильтрация** по полному набору токенов запроса (все значимые слова и числа должны встречаться в агрегированном тексте оффера). |
| **hybrid_rrf_nofilter** | То же **RRF**, **без** постфильтрации по токенам — контрольная линия для оценки вклада фильтра в точность. |

## 4. Метрики

Для каждого запроса строится упорядоченный список `offer_id` (предсказание). Для множества релевантных `R` и префикса предсказания длины `K`:

- **Recall@K** — доля найденных релевантных документов среди всех релевантных:  
  `|{первые K предсказаний} ∩ R| / |R|`.

- **MRR@K** (Mean Reciprocal Rank) — для запроса: `1 / rank` первого релевантного документа в пределах первых `K` позиций; если нет — `0`. В отчёте усредняется по запросам (**macro**).

- **nDCG@K** — нормалированный дисконтированный накопленный выигрыш; релевантность бинарная (1 / 0); идеальный порядок — все релевантные в начале.

В отчёте `evaluation/reports/vkr_metrics.md` усреднение по всем запросам набора.

## 5. Воспроизведение

```bash
python -m scripts.evaluate_vkr
python -m scripts.evaluate_vkr --dry-run      # без записи category-aware нормализации в БД (Task 3)
python -m scripts.evaluate_vkr --task7-only   # только оценка поиска, без Task 2/3
```

Артефакты: `evaluation/reports/vkr_metrics.json`, `vkr_metrics.md` (и варианты `*_dry_run.*`).

В JSON поле `task7` содержит метаданные эксперимента и массив `per_query` с метриками по каждому запросу.

## 6. Интерпретация для сравнительного анализа

- **semantic_only** — сильная сторона: синонимы и перефраз; слабая: точные модели/артикулы без явного совпадения в корпусе.
- **text_only** — сильная сторона: точные совпадения по словам; слабая: пропуски при другой лексике.
- **hybrid_rrf** — объединение каналов; **hybrid_rrf_nofilter** показывает эффект только RRF без жёсткой согласованности с токенами запроса.
- **hybrid_rrf** (с фильтром) обычно ближе к ожиданиям пользователя витрины при многословных запросах за счёт отсечения ложных семантических попаданий.
